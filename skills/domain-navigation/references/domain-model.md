# Domain model

Group a Domain around a capability and its ownership, state, and authority. Directory boundaries can provide evidence, but a folder by itself does not define a Domain.

A useful Domain Map identifies each domain's responsibility and boundaries, owner or authority, primary entry points and symbols, dependencies and consumers, relevant tests, invariants, and evidence paths. Split a domain into a detailed `DOMAIN.md` only when that added detail is justified by the project's size or navigation needs.

The map helps an agent find and verify project sources. It does not replace those sources or become authority for product, data, or runtime facts.
