# Evidence rules

Inspect the project's intent documents and source code before describing architecture or ownership. Support non-trivial claims with concrete repository paths and, where useful, symbols, tests, or runtime entry points.

Separate direct observations from interpretation. If evidence is missing, stale, or conflicting, leave the claim unresolved and identify what would verify it. A Domain Map and any other derived navigation output do not become product, domain, data, or runtime authorities.
