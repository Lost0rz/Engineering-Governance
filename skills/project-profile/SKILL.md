# Project Profile

Create, shrink, rebuild or audit a **compact derived context and authority index**. Do not use for ordinary engineering status, current PR/Task progress or detailed Domain-to-code navigation. This Skill never creates implementation or Profile-write authorization.

## Minimal route

- **Reuse an existing Profile:** consume it directly as derived orientation; no Project Profile invocation or contract reload is necessary.
- **Create/rebuild/change:** read [profile-contract.md](references/profile-contract.md) and [the template](assets/templates/PROJECT_PROFILE.md) once; verify only task-relevant project authorities. A repository/project-managed write needs current Project Governance authorization.
- **Audit only:** read the candidate Profile and claim-relevant owning sources; return findings without changing a file. Refresh only stale durable claims when authorized.
- **Request about Profile format:** explain succinctly without scanning every project source.

## Grounding and output

Trace substantive project facts to current verified project authorities or explicit current-task user direction; Memory, old chats, previous Profiles and assistant summaries are leads, **not independent fact authority**. Retain stable purpose, concepts, durable/version-scoped boundaries, environment roles and concise authority pointers. Omit temporary paths/ports, live Task/CI/incident state, full Skill routing and engineering procedures.

Use the template's fixed `Profile surface` and `Primary/mirror role` fields; never invent multiple surfaces or a primary. `AGENTS.md`, the active Task/Issue, owning Domain/planning authority and observed runtime/source facts outrank this derived Profile.

For a **new, revised or audited Profile**, apply the existing [Profile contract](references/profile-contract.md): grounding, durability, classification, authority-map compression, output and its mandatory pre-return compliance check. A Profile itself never authorizes the work it summarizes. Return the compact result or specific findings, not a separate governance handbook.
