## Engineering Governance Skill routing

For ordinary software, repository, or project engineering work, use `project-governance` as the normal entry unless a higher-priority instruction or explicit bounded Skill selection determines another route. Keep simple work lightweight.

Use `project-profile` only when creating, rebuilding, shrinking, or auditing the compact derived project context/index. It is not task authority or a Domain Map replacement.

Use `solution-design` for material design ambiguity; `execution-orchestrator` for useful decomposition/delegation/recovery; `agent-handoff` for bounded cross-context transfer; `evidence-audit` for read-only evidence/readiness verdicts; `domain-navigation` for unclear semantic/source/test/runtime routes; and `incident-doctor` only for a blocking evidence gap.

Keywords alone do not select a Skill. These capabilities compose without creating parallel task authority. Follow the selected Skill and the target repository's own authorities for project facts.
