# Normal development flow

1. Read applicable repository guidance and current task controls; inspect only the project evidence needed to understand the authorized work.
2. Confirm objective, affected domains, scope, acceptance, risk, and verification before implementation. Treat an out-of-scope request as a task change that needs authorization.
3. Prefer the next useful product or business outcome. Use Domain Navigation when the relevant code or authority is unclear.
4. Change only what the active task authorizes. Keep derived analysis distinct from project facts and decisions.
5. Verify at the task's chosen level, record observed results, and update current controls when verified state materially changes.
6. Stop at the task's handoff point. Report unresolved evidence and blockers without claiming acceptance that belongs to an independent reviewer or user.

Enter Incident Doctor only for a real failure, unexplained behavior, or unsafe ambiguity that blocks progress and cannot be answered from existing evidence. Otherwise continue normal work without adding diagnostic infrastructure.
