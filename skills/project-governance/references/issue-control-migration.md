# Historical FILE_CONTROL to ISSUE_CONTROL enrollment

Use only for a repository actually migrating its task-authority system, not for ordinary development.

## Verified adoption

1. Confirm canonical repository and globally installed `CONTROL_POLICY_V1`.
2. Identify the real merged migration PR, verify its governance-specific changes and that the merge belongs to current `main` ancestry.
3. Read accepted project-specific `AGENTS.md` and current trust/permission evidence from GitHub; editable local claims alone do not establish enrollment.
4. Move future task selection to ISSUE_CONTROL through the installed policy. Preserve project-specific constraints and any intentionally retained legacy histories.
5. Verify a representative read-only route and one authorized source-write route before declaring runtime adoption.

If proof is missing, keep the previously authorized route for safe read-only work and resolve the migration before a dependent write. Migration does not automatically rewrite prior Issues, delete control files or grant future unattended autonomy.
