# Planning and durable decisions

A plan is useful when it reduces uncertainty or lets another context recover an important design choice. It is not a mandatory artifact for every code edit.

An Issue, PR description, project document or current conversation can hold the plan. Choose the surface that is easiest to update and read; do not create duplicate controls or status files.

A useful plan explains the goal, evidence, intended changes, meaningful risks, affected interfaces/tests and remaining decisions. Use only the amount of structure that improves execution. New information can update the plan without an editor whitelist or signature ritual.

Implementation source and runtime evidence stay with code/CI; actual writer permission stays with the host. A design plan is not a grant, but it can be reused by the AI once the current task is authorized.
